# Li-MACE Defective Graphene Pipeline

This project scaffolds an end-to-end workflow for Li diffusion in defective
graphene and Si-graphene anodes using MACE fine-tuning and LAMMPS-MACE MD.

## Files

- `setup_env.sh`: create the `mace_md` Conda environment.
- `download_mace.py`: download the MACE-MPA-0 medium foundation model.
- `build_defect_structures.py`: generate VASP POSCAR inputs for perfect,
  vacancy, Stone-Wales, and Si-graphene structures with Li.
- `vasp_to_extxyz.py`: convert `dft_outputs/**/OUTCAR` into
  `data/train_data.extxyz`.
- `inspect_mace_model.py`: inspect the MACE model before fine-tuning and verify
  that `mace_run_train` supports the required LR-factor controls.
- `run_finetune.sh`: fine-tune MACE and convert the trained model for LAMMPS.
- `convert_model_for_lammps.py`: standalone wrapper around
  `mace.cli.create_lammps_model`.
- `build_lammps_data.py`: replicate an optimized small structure into a LAMMPS
  atomic data file.
- `prepare_vasp_jobs.py`: create VASP input/job folders under `dft_outputs/`.
- `install_lammps_mace_gpu.sh`: build LAMMPS with ML-MACE and KOKKOS CUDA.
- `in.lammps_diffusion`: NVT diffusion input using `pair_style mace`.
- `submit_*.slurm`: Slurm wrappers for `et2024` CPU and `et_gpu` GPU partitions.

## Run Order

1. Create the Python environment:

   ```bash
   bash setup_env.sh
   ```

2. Generate VASP starting structures on CPU:

   ```bash
   PATH=/usr/local/slurm/bin:$PATH sbatch submit_cpu_data_prep.slurm
   ```

   This writes POSCARs under `structures/vasp/`.

3. Run VASP calculations outside this scaffold, placing results as:

   ```text
   dft_outputs/<case_name>/OUTCAR
   ```

   To prepare those VASP job folders automatically:

   ```bash
   conda activate mace_md
   python prepare_vasp_jobs.py --mode relax
   ```

   This creates one directory per structure under `dft_outputs/`, each with
   `POSCAR`, `INCAR`, `KPOINTS`, and `submit_vasp.slurm`.

   VASP pseudopotentials are licensed files and are not generated by default.
   If your PAW_PBE potential root is known, pass it explicitly:

   ```bash
   python prepare_vasp_jobs.py --mode relax --potcar-root /path/to/potpaw_PBE
   ```

   Otherwise, open each `dft_outputs/<case>/POTCAR_REQUIRED.txt` and concatenate
   `POTCAR` manually in the listed element order. Then submit each VASP job:

   ```bash
   cd dft_outputs/A_Perfect
   PATH=/usr/local/slurm/bin:$PATH sbatch submit_vasp.slurm
   ```

   Use `module load vasp/5.4.1` inside these jobs; this exposes `vasp_std`.

4. Convert OUTCAR files to MACE training data:

   ```bash
   conda activate mace_md
   python vasp_to_extxyz.py --input-glob "dft_outputs/**/OUTCAR" --output data/train_data.extxyz
   ```

5. Download the foundation model:

   ```bash
   conda activate mace_md
   python download_mace.py --destination models/foundation
   ```

   If the cluster cannot reach Hugging Face, manually place the model at:

   ```text
   models/foundation/mace-mpa-0-medium.model
   ```

6. Submit MACE fine-tuning on GPU:

   ```bash
   PATH=/usr/local/slurm/bin:$PATH sbatch submit_gpu_finetune.slurm
   ```

   The script uses `--lr_params_factors` to keep embedding and interaction
   parameters fixed while leaving products/readouts trainable. It does not use a
   brittle numeric `--freeze` index.

7. Build a large LAMMPS data file from an optimized small cell:

   ```bash
   conda activate mace_md
   python build_lammps_data.py \
       --input structures/optimized/CONTCAR \
       --repeat 10 10 1 \
       --output data/lammps/defective_graphene.data
   ```

   For a stacked multilayer system, explicitly request the z layers:

   ```bash
   python build_lammps_data.py --input structures/optimized/CONTCAR --repeat 10 10 4
   ```

8. Build LAMMPS-MACE on the GPU partition:

   ```bash
   PATH=/usr/local/slurm/bin:$PATH sbatch submit_gpu_install_lammps.slurm
   ```

   If the CUDA toolkit is not visible on the GPU node, set `MODULE_LOADS` before
   submission, for example:

   ```bash
   MODULE_LOADS="gcc/12.2.0 mpi/openmpi-4.1.1_gcc cmake/3.26.1 cuda/12.1" \
       sbatch submit_gpu_install_lammps.slurm
   ```

9. Submit LAMMPS MD:

   ```bash
   PATH=/usr/local/slurm/bin:$PATH sbatch submit_gpu_lammps.slurm
   ```

   The GPU command inside the Slurm file is:

   ```bash
   mpirun -np 1 "$LAMMPS_BIN" -k on g 1 -sf kk -in in.lammps_diffusion
   ```

## Smoke Tests

Run these before submitting long jobs:

```bash
bash -n *.sh submit_*.slurm
python -m py_compile *.py
conda activate mace_md
python inspect_mace_model.py models/foundation/mace-mpa-0-medium.model --check-train-cli
MAX_NUM_EPOCHS=2 START_SWA=1 bash run_finetune.sh
```

For LAMMPS, reduce `variable nsteps` in `in.lammps_diffusion` to 10 or 100 for
the first GPU smoke test.

## Notes

- `in.lammps_diffusion` assumes LAMMPS atom types map to `C Li Si`. Keep
  `build_lammps_data.py --specorder C Li Si` aligned with the `pair_coeff`.
- The default LAMMPS interface is legacy `pair_style mace`, so converted models
  are `*-lammps.pt` files created with `--format=libtorch`.
- ML-IAP conversion is available through `convert_model_for_lammps.py --format=mliap`
  but is not the default because the input file targets `pair_style mace`.
